# План реализации офлайн-CRM «РИТМ»

Дата: 2 ноября 2026  
Основание: 7 макетов Figma (`aCk57y8xXe8mrnnQpcgZKz`), снимки сохранены в `docs/mockups/`.  
Формат: настольное офлайн-приложение для одной студии, без сервера и облака.

---

## 1. Цель

Собрать рабочее CRM-приложение для студии красоты по макетам:

- расписание на день, месяц и год;
- создание и редактирование записи клиента;
- прайс-лист услуг и добавление услуги;
- статистика продаж услуг;
- клиенты и настройки — как служебные разделы, необходимые для работы.

Главное требование: **приложение полностью работает без интернета, все данные хранятся на устройстве**.

---

## 2. Что входит в MVP

| Блок | Состав |
|---|---|
| Расписание | День / месяц / год, фильтр по специалисту, переходы по датам, сводка по записям и плановой выручке |
| Записи | Создание, редактирование, отмена, статусы, выбор клиента, специалиста и услуг, проверка пересечений |
| Услуги | Список, поиск, категории, активность, добавление и редактирование, архивирование |
| Клиенты | Поиск, создание, карточка, история записей, сумма покупок |
| Статистика | Выручка, записи, прибыль, средний чек, график, специалисты, лидеры продаж, CSV |
| Настройки | Студия, специалисты, категории, резервные копии, мастер первого запуска |
| Офлайн | IndexedDB, автосохранение, экспорт/импорт JSON, авторезервные копии |

### Не входит в MVP

- облачная синхронизация и работа с нескольких устройств;
- авторизация, роли и права доступа;
- онлайн-запись, SMS/email-уведомления, оплата;
- интеграции с телефонией, WhatsApp, 1С, бухгалтерией;
- склад, зарплаты, расходы, закупки;
- мобильная вёрстка (интерфейс проектируется под 1440×1000, минимум 1200×800);
- импорт из Excel и других CRM;
- подписанный установщик и автообновления.

## 3. Ограничения и принятые решения

### Ограничения агента

1. Figma доступна только на просмотр: нет токена и Dev Mode, поэтому точные отступы, шрифты и токены не выгружаются. Работаем по снимкам, цвета и размеры калибруем итеративно.
2. Нет облачного бэкенда, платных API и хостинга. Всё приложение — локальный статический билд.
3. Нет Rust/Tauri. Для настольной упаковки используем Electron (Node.js 20 и npm уже установлены).
4. Тестирование интерфейса — в браузере на этой машине; проверить приложение на macOS, Linux и реальных мобильных устройствах я не могу.
5. Установщик не подписан: Windows SmartScreen может показать предупреждение.
6. Я не смогу восстановить данные, если пользователь очистит хранилище приложения. Поэтому обязательны резервные копии.
7. Пиксельного совпадения с макетом «до пикселя» не гарантирую; гарантирую совпадение структуры, логики и близкую визуальную стилистику.

### Решения по умолчанию

| Вопрос | Решение |
|---|---|
| Формат поставки | Electron-приложение (portable `.exe`) + тот же билд запускается в браузере для разработки |
| Хранилище | IndexedDB через Dexie; файловые резервные копии JSON |
| Пользователь | Один администратор, без входа и пароля |
| Синхронизация | Нет. Вместо «Синхронизировано» показываем «Сохранено локально» |
| Клиенты | Добавляем отдельный раздел, иначе клиентами нельзя управлять вне записи |
| Первый запуск | Чистая установка: мастер настройки студии, команды и прайса, без демо-данных |
| Прибыль | Считаем как выручку минус себестоимость услуги; себестоимость — необязательное поле |
| Валюта и язык | Рубли, русский язык, часовой пояс устройства |
| Разрешение | 1440×1000, минимальное окно 1200×800 |

## 4. Стек

| Слой | Технологии |
|---|---|
| UI | React 18 + TypeScript 5, Vite, Tailwind CSS 3.4, CSS-переменные |
| Компоненты | Radix UI (dialog, popover, select, tabs, toast, tooltip), lucide-react |
| Формы | react-hook-form + zod |
| Роутинг | React Router 6, `HashRouter` (совместим с `file://` и `app://`) |
| Состояние | Dexie live queries + Zustand для UI-состояния |
| Данные | Dexie 4 (IndexedDB), версионирование схемы и миграции |
| Даты | date-fns 3, локаль `ru` |
| Графики | Recharts 2 |
| Импорт Excel | SheetJS (`xlsx`), чтение XLSX/XLS/CSV в браузере и Electron |
| Шрифт | Manrope (OFL), подключается локально через `@fontsource/manrope` |
| Тесты | Vitest + Testing Library + jsdom |
| Настольная оболочка | Electron (актуальная стабильная версия), electron-builder (portable) |
| Качество | ESLint, Prettier, strict TypeScript |

Принципы:

- **Никаких CDN и внешних запросов в runtime.** Шрифты, иконки, графики — в бандле.
- **Никаких `localStorage` для доменных данных.** Только IndexedDB; `localStorage` — для мелких UI-настроек.
- **Даты и время — локальные строки** `YYYY-MM-DD` и `HH:mm`, без UTC, чтобы не ломаться на переходе часов.
- **Деньги — целые рубли**, длительность — целые минуты. Без плавающей точки.
- **ID — UUID** (`crypto.randomUUID()`).

```
┌──────────────────────────▼──────────────────────────────┐
│ Renderer: React SPA                                      │
│                                                          │
│  features/schedule   features/services   features/stats  │
│  features/clients    features/settings                   │
│           │                  │                           │
│           ▼                  ▼                           │
│  domain: типы, валидация, расчёт расписания и статистики │
│           │                                              │
│           ▼                                              │
│  db: Dexie schema, миграции, репозитории, seed, backup   │
│           │                                              │
│           ▼                                              │
│  IndexedDB (локально, на устройстве)                     │
└─────────────────────────────────────────────────────────┘
```

- Компоненты не ходят в Dexie напрямую: только через репозитории.
- Чтение — `useLiveQuery`, поэтому таблицы и счётчики обновляются после любой мутации.
- Запись — в транзакции: запись + строки услуг + пересчёт итогов.
- Ошибки домена возвращаются типизированно (`{ code, message, details }`), UI показывает их в тосте или под полем.
- `ErrorBoundary` на уровне приложения: кнопка перезапуска и ссылка на инструкцию по бэкапу.

## 6. Модель данных

### Сущности

```ts
type AppointmentStatus =
  | 'pending'    // Ожидает подтверждения
  | 'confirmed'  // Подтверждена
  | 'completed'  // Выполнена
  | 'cancelled'  // Отменена
  | 'no_show';   // Не пришёл

interface Settings {
  id: 'app';
  studioName: string;
  address: string;
  phone: string;
  workdayStart: string;      // '09:00'
  workdayEnd: string;        // '18:00'
  weekStart: 'monday';
  demoMode: boolean;
  lastBackupAt?: string;
}

interface Specialist {
  id: string;
  name: string;
  role: string;              // 'Мастер', 'Администратор'
  color: string;             // цвет колонки/аватара
  active: boolean;
  serviceIds: string[];      // какие услуги оказывает
}

interface Category {
  id: string;
  name: string;              // Волосы, Ногти, Брови
  order: number;
}

interface Service {
  id: string;
  categoryId: string;
  name: string;
  durationMin: number;
  priceRub: number;
  costRub?: number;          // для расчёта прибыли
  description?: string;
  specialistIds: string[];
  active: boolean;
  createdAt: string;
  updatedAt: string;
}

interface Client {
  id: string;
  firstName: string;
  lastName: string;
  phone: string;
  phoneNormalized: string;   // только цифры, для поиска
  email?: string;
  birthday?: string;
  notes?: string;
  createdAt: string;
  updatedAt: string;
}

interface Appointment {
  id: string;
  clientId: string;
  specialistId: string;
  date: string;              // 'YYYY-MM-DD'
  startTime: string;         // '14:00'
  durationMin: number;       // сумма услуг
  status: AppointmentStatus;
  comment?: string;
  totalRub: number;          // снимок суммы
  createdAt: string;
  updatedAt: string;
}

interface AppointmentService {
  id: string;
  appointmentId: string;
  serviceId: string;
  nameSnapshot: string;      // история не меняется при редактировании услуги
  priceRub: number;
  costRub?: number;
  durationMin: number;
}
```

### Индексы и правила

- `appointments`: `date`, `specialistId`, `clientId`, `status`, составной `[date+specialistId]`.
- `clients`: `phoneNormalized`, `lastName`.
- `services`: `categoryId`, `active`.
- `appointmentServices`: `appointmentId`, `serviceId`.
- Услуги и цены в записи **снимаются на момент сохранения**. Изменение прайса не переписывает историю.
- Удаление услуги, которая уже использовалась, запрещено — только архивирование (`active=false`).
- Удаление клиента с записями запрещено; можно архивировать.
- Запись не удаляется физически: статус `cancelled`, чтобы сохранить историю.

### Первый запуск

- Новая установка открывает мастер настройки, а не заполненную демонстрационную базу.
- Шаг 1: название студии, адрес, телефон, рабочие часы.
- Шаг 2: специалисты — имя, роль, цвет; требуется хотя бы один.
- Шаг 3: категории и услуги — название, категория, цена, длительность; шаг можно пропустить.
- Шаг 4: сводка и кнопка «Начать работу».
- Все настройки сохраняются одной транзакцией; услуги становятся доступны всем добавленным специалистам.
- «Очистить всё» удаляет данные и возвращает мастер первого запуска.

## 7. Экраны и поведение

### 7.1. Каркас приложения

- Сайдбар 220 px: логотип «РИТМ», карточка студии, навигация (Расписание, Услуги, Клиенты, Статистика), помощь, пользователь.
- Верхняя панель: хлебные крошки, текущая дата, статус хранения, уведомления.
- Статус вместо «Синхронизировано»: «Сохранено локально» / «Сохранение…» / «Офлайн — данные доступны».
- Все страницы — в одном окне, без перезагрузок.

### 7.2. Расписание — день

- Заголовок «Расписание», подзаголовок, кнопка «+ Новая запись».
- Панель: «Сегодня», стрелки, дата, фильтр специалиста, переключатель День / Месяц / Год.
- Сводка: «N записей · M специалистов · Плановая выручка X ₽».
- Сетка времени от `workdayStart` до `workdayEnd`; колонки по специалистам.
- Карточка записи: время, клиент, услуга(и), цена, цвет статуса; позиция и высота зависят от времени и длительности.
- Клик по пустой ячейке — новая запись с подставленными датой, временем и специалистом.
- Клик по карточке — редактирование.
- Линия текущего времени для сегодняшнего дня.
- Пересечения внутри одной колонки раскладываются рядом; при создании конфликт блокируется.

### 7.3. Расписание — месяц

- Сетка 7 колонок, неделя с понедельника, 5–6 строк.
- В ячейке: число, количество записей, до 2 записей (время + клиент), «Ещё N».
- Сегодня — обводка, выбранный день — заливка `#EAF2ED`, выходные — приглушённый фон.
- Клик по дню — переход в день; клик по записи — редактирование.
- Сводка за месяц и навигация по месяцам.

### 7.4. Расписание — год

- 12 карточек месяцев (4×3), в каждой: название, количество записей, мини-теплокарта 7×6.
- Клик по месяцу — переход в месяц; навигация по годам.
- Итог за год и легенда «меньше / больше».
- Детальные записи в годе не показываем — только агрегаты.

### 7.5. Модальное окно записи

Создание и редактирование:

- шапка: «Новая запись» / «Редактирование записи», дата и клиент;
- клиент: поиск по имени/телефону, список, «Создать клиента» прямо в окне;
- телефон: маска `+7 (___) ___-__-__`;
- дата, время (шаг 15 минут), длительность (авто из услуг, можно изменить);
- специалист: только те, кто оказывает выбранные услуги;
- статус: ожидает / подтверждена / выполнена / отменена / не пришёл;
- услуги: поиск, группировка по категориям, чекбоксы, выбранные строки с ценой и длительностью;
- быстрое создание услуги прямо в окне записи: название, категория (включая новую), цена и длительность; созданная услуга сразу выбирается в запись;
- итог: количество услуг, общая длительность, сумма;
- комментарий;
- конфликт: баннер «У специалиста уже есть запись 14:00–15:30»; сохранение блокируется, пока конфликт не устранён;
- кнопки: «Отменить запись» (для существующей), «Сохранить».

Валидация: клиент, специалист, дата, время и хотя бы одна услуга обязательны; время в пределах рабочих часов; длительность > 0.

### 7.6. Услуги

- Заголовок, подзаголовок, «+ Добавить услугу».
- Табы категорий с количеством, поиск, фильтр «Активные».
- Таблица: услуга (название + описание), категория, длительность, цена, статус, меню действий.
- Действия: редактировать, архивировать/вернуть, удалить (если не использовалась).
- Панель добавления/редактирования справа: название, категория, цена, длительность, описание, специалисты, тумблер «Доступна для записи».
- Импорт прайса из Excel: загрузка XLSX/XLS/CSV, выбор листа и строки заголовков, ручное сопоставление колонок, предпросмотр, создание категорий и специалистов, обновление совпадающих услуг.
- Валидация: название, категория, цена ≥ 0, длительность кратна 15 минутам.

### 7.7. Клиенты (расширение к макету)

- Поиск по имени и телефону, «+ Новый клиент».
- Таблица: имя, телефон, количество визитов, последний визит, сумма.
- Карточка клиента: контакты, комментарий, заметки, история записей, сумма, кнопка «Новая запись».
- Удаление — только если нет записей; иначе архивирование.

### 7.8. Статистика

- Фильтры: период (месяц + стрелки, позже — произвольный диапазон), специалист, услуга.
- Кнопка «Скачать отчёт» (CSV).
- KPI: выручка, записи, прибыль, средний чек; дельта к предыдущему периоду.
- График «Выручка» по неделям месяца или по месяцам года.
- Блок «По специалистам»: сумма и доля.
- Таблица «Лидеры продаж»: услуга, записи, средняя цена, выручка, доля.
- Пустое состояние, если за период нет выполненных записей.

Формулы:

- выручка = сумма `totalRub` выполненных записей;
- записи = все, кроме отменённых и не пришедших;
- средний чек = выручка / количество выполненных;
- прибыль = выручка − сумма `costRub` выполненных услуг; если себестоимости нет — «—»;
- доля услуги = выручка услуги / выручка периода;
- дельта = (текущий − предыдущий) / предыдущий × 100%, при нулевой базе — «—».

### 7.9. Настройки

- Студия: название, адрес, телефон, рабочие часы.
- Специалисты: список, имя, роль, цвет, услуги, активность.
- Категории: название и порядок.
- Данные: экспорт JSON, импорт JSON, авторезервные копии, состояние хранилища, полная очистка с возвратом к мастеру настройки.
- О приложении: версия, лицензии шрифта/иконок, инструкция по бэкапу.

### 7.10. Первый запуск

- Мастер из четырёх шагов: студия → команда → прайс → готово.
- Проверка обязательных полей, рабочие часы и хотя бы один специалист.
- Шаг прайса можно пропустить; услугу затем можно создать в разделе «Услуги» или из карточки записи.
- Прогресс слева, навигация «Назад / Продолжить», сохранение одной транзакцией.

### 7.11. Общие элементы

- Тосты об успехе и ошибках.
- Подтверждение опасных действий.
- Пустые состояния с призывом к действию.
- Скелетоны при первой загрузке.
- Escape закрывает модалки, Enter отправляет форму, фокус-трап в диалогах.
- Все подписи и сообщения — на русском.

## 8. Офлайн-хранилище и сохранность данных

1. `navigator.storage.persist()` при первом запуске; в настройках показываем, предоставлено ли постоянное хранилище.
2. Автосохранение каждой мутации в IndexedDB; отдельной кнопки «Сохранить» нет.
3. Резервная копия:
   - ручной экспорт в JSON через диалог Electron;
   - авторезервная копия при закрытии приложения и раз в сутки;
   - храним 10 последних копий в `userData/backups`;
   - импорт с проверкой версии, структуры и обязательных полей; режим «заменить» или «добавить».
4. При первом запуске открывается мастер настройки; база не заполняется демонстрационными данными.
5. В веб-режиме (разработка) экспорт скачивается файлом, импорт — через выбор файла.
6. В шапке показываем дату последней резервной копии, если она старше 7 дней — предупреждение.

## 9. Этапы реализации

Оценка — ориентир для планирования, а не жёсткий срок. Каждый этап заканчивается рабочим приложением и коротким отчётом.

| Этап | Содержание | Результат | Приёмка |
|---|---|---|---|
| 0. Каркас | Vite + React + TS + Tailwind, роутер, шрифт, токены, сайдбар, топбар, пустые страницы | Приложение запускается, выглядит как каркас макета | Нет ошибок в консоли; 1440×1000; навигация работает |
| 1. Данные | Dexie-схема, репозитории, мастер первого запуска, настройки, backup/restore, тесты схемы | Чистая база и рабочий мастер настройки | Новая установка открывает мастер; данные сохраняются после перезагрузки; экспорт/импорт проходит round-trip |
| 2. Услуги | Список, фильтры, добавление/редактирование, архивирование, быстрое создание из записи, импорт Excel | Полный CRUD услуг и загрузка прайса | CRUD и валидация; услуга из карточки записи сразу выбирается в запись; импорт с сопоставлением колонок |
| 3. Клиенты и специалисты | Справочник клиентов, быстрый create, CRUD специалистов в настройках | Можно управлять клиентской базой | Поиск по телефону; история; нельзя удалить клиента с записями |
| 4. Расписание — день | Сетка, колонки, карточки, создание/редактирование записи, конфликты | Основной рабочий экран | Запись сохраняется, переживает reload, конфликт блокируется |
| 5. Месяц и год | Календари, агрегаты, переходы | Все три режима расписания | Счётчики совпадают с данными; переход день↔месяц↔год |
| 6. Статистика | Агрегации, KPI, график, специалисты, лидеры, CSV | Экран статистики | Цифры сходятся с независимым расчётом; фильтры; CSV открывается в Excel |
| 7. Офлайн и полировка | PWA-манифест (опционально), проверка offline, пустые состояния, тосты, доступность | Приложение готово к использованию в браузере | Reload без сети; данные на месте; клавиатура и фокус |
| 8. Electron | Оболочка, `app://`, диалоги бэкапа, авторезервные копии, portable exe | `RITM-CRM-portable.exe` | Запуск без Node и интернета; данные сохраняются между запусками |
| 9. QA и передача | Unit-тесты, smoke-сценарии, сравнение с макетами, README | Финальная сборка и инструкция | Чек-лист из раздела 10 пройден |

Порядок работы: после каждого этапа показываю результат, мы сверяем с макетом и только потом идём дальше. Это снижает риск, что ошибка в модели данных всплывёт на статистике.

## 10. Тестирование и качество

### Unit-тесты

- расчёт длительности и суммы записи;
- поиск пересечений;
- агрегаты дня, месяца, года;
- статистика, дельты, доли, средний чек;
- нормализация телефона и поиск;
- валидация импорта и миграции схемы.

### Ручные сценарии

1. Первый запуск: мастер настройки, пустая база, реальная текущая дата.
2. Создать клиента и запись; перезагрузить — запись на месте.
3. Попытка поставить две записи одному специалисту на одно время — блокировка.
4. Изменить цену услуги — старая запись сохраняет старую сумму.
5. Архивировать услугу — она исчезает из выбора, старые записи целы.
6. Месяц и год: счётчики и переходы.
7. Статистика: фильтры, KPI, CSV.
8. Экспорт бэкапа → очистка → импорт → данные восстановлены.
9. Отключить сеть → перезагрузить → приложение работает.
10. Electron: запуск exe, данные между запусками, диалог бэкапа.
11. Импорт Excel: файл с шапкой и нестандартными заголовками; автоматическое и ручное сопоставление; новые категории и специалисты; повторный импорт обновляет услуги без дублей.

### Визуальная сверка

- 1440×1000, светлая тема.
- Токены: `#376451` (primary), `#F6F7F8` (фон), `#FFFFFF` (карточки), `#EAF2ED` (выделение), `#E5E9E6` (границы), `#202725` (текст), `#69716D` (вторичный текст).
- Сравнение с `docs/mockups/*.png` по каждому экрану.

### Производительность

- день: < 100 мс на выборку и отрисовку при 250 записях в месяц;
- месяц: один диапазонный запрос;
- год: 12 агрегатов, без загрузки всех записей в память;
- графики — не более 31 точки.

## 11. Риски и меры

| Риск | Мера |
|---|---|
| Расхождения с макетом из-за отсутствия токенов Figma | Снимки в репозитории, калибровка цветов/отступов, итеративная сверка |
| Потеря данных при очистке хранилища | `storage.persist()`, авторезервные копии, ручной экспорт, предупреждение в настройках |
| Сложность Electron-сборки | Сначала веб-версия, Electron — отдельным этапом; fallback — запуск статики через локальный сервер |
| SmartScreen/антивирус на неподписанном exe | Документируем предупреждение; подпись — позже |
| Часовые пояса и летнее время | Локальные строки даты/времени, без UTC |
| Разрастание объёма | Жёсткий список MVP; всё остальное — после приёмки |
| Ошибки в миграциях IndexedDB | Версионирование, тесты миграций, бэкап перед обновлением |
| Пересечения записей | Алгоритм раскладки + блокировка конфликта |
| Шрифт без кириллицы | Manrope с проверкой кириллического сабсета; fallback — system-ui |
